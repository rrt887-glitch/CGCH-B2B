# 多家客户（多租户 SaaS）

一套系统同时卖给多家企业：每家公司有自己的后台、员工和渠道账号（Facebook / Instagram / TikTok / WhatsApp / 邮箱 / 官网在线客服），数据互相隔离。所有客户共用一个网址。

## 账号与权限

| 账号 | 在哪 | 能做什么 |
| --- | --- | --- |
| 平台超级管理员（你） | 1 号租户（平台） | 「客户管理」：开户、改账号数、到期、停用；默认**看不到**客户的业务数据；需要支持时「进入客户后台」 |
| 客户管理员 | 每家客户 | 本公司全部功能；看得到本公司**所有成员**的会话和客户；在「设置 › 成员」添加员工；能看到平台进入本公司后台的记录 |
| 成员 | 每家客户 | 日常接待、跟进；只看**自己负责的**会话和客户，以及同事**公开给团队**的会话 |

- 登录账号用**邮箱或手机号**，全平台唯一。登录页只填账号和密码，系统按账号找到所属公司，不需要选公司（客户名单不会在登录页暴露）。
- 老账号（例如 `admin`）照样能登录，新建账号必须是邮箱或手机号。
- 开户只建客户的管理员；系统同时为这家公司建好「成员」角色（权限以平台里的「业务员」角色为模板）和 CRM 初始数据（外贸标准商机流程、公海规则）。账号数上限默认 5（含管理员），剩下的由客户管理员自己添加，超过上限会提示联系平台。
- 套餐「客户标准版」：草根出海全部功能 + 成员管理，不含平台功能（租户、套餐、系统配置）和智点充值。
- 大模型由客户自己在「设置 › AI 接待设置」里填（服务商、API Key、模型），费用在客户自己的账户。

## 公开给团队

会话右侧「公开给团队」开关：负责人或管理员打开后，本公司全部成员都能在「团队会话」里看到这个会话，可以看消息、写内部备注，不能回复客户、改状态或转交；会话动态里会记录谁公开 / 取消了公开。

## 进入客户后台

「客户管理 › 进入后台」需要填写原因，进入后 2 小时内有效，页面顶部显示正在查看哪家客户，可随时退出。

- 没有经过这个入口，带 `visit-tenant-id` 请求头访问也会被拒绝；
- 每次进入都记录时间、人员、原因、IP，平台可在「进入记录」里查，客户管理员在「设置 › 成员 › 平台访问记录」里能看到；
- 进入期间按管理员身份看这家客户的全部数据。

## 上线步骤

1. 合并到 main，等 GitHub Actions 发布镜像成功。
2. 备份数据库和 `/opt/cgch/.env`。
3. 服务器上重新执行安装命令（会自动执行数据库升级 `034-saas-tenancy.sql`）。
4. 用 `admin` 登录，确认左侧出现「客户管理」，并修改 `admin` 的默认密码。
5. **把 HIG 搬成独立客户**（推荐，否则 HIG 的员工在平台租户里，能管理所有客户）：
   按 [`backend/sql/mysql/cgch/manual/move-tenant1-business-to-new-tenant.sql`](../backend/sql/mysql/cgch/manual/move-tenant1-business-to-new-tenant.sql) 文件开头的步骤执行（先在「客户管理」给 HIG 开户，再执行脚本）。
6. 用新客户的管理员登录检查会话、客户、渠道；把登录地址、账号、密码交给客户。

## WhatsApp 出口代理（扫码接入）

扫码接入的号码都跑在同一台 Evolution 服务上。如果不配代理，所有客户的消息都从平台服务器同一个 IP 出去，
一家客户群发被风控，同一个 IP 上的号码都更容易被限制。

「客户管理 › 出口代理」给每家客户配一个自己的代理（http / https / socks4 / socks5，可带账号密码）：

- 只允许平台配置（需要 `system:tenant:update`），客户的管理员和成员看不到也改不了；
- 密码加密保存，接口只回 `hasPassword`，不回密码本身；
- **扫码建实例时会先设置代理再出二维码**，保证第一次连接就用客户的出口；代理连不上时直接报错，不会留下半成品实例；
- 保存时勾选「保存并应用」会把代理设置到这家客户**已有的号码**上，正在连接的号码需要重新连接才按新出口走；
- 关闭开关并应用后，号码改回直连。

## 限制与后续

- 所有客户扫码接入的 WhatsApp 号码共用一台 Evolution 服务（同一进程）。按客户配出口代理只能做到「出口 IP 隔离」，
  进程与资源仍是共用的：一家客户大量同步历史或群发，仍会拖慢其他客户。客户多了之后需要 Evolution 多副本按客户分片。
- 扫码接入本身违反 WhatsApp 条款，技术手段只能降低风险、不能消除，服务条款里要写明封号风险由客户承担。
- 每号码发送上限（设置 › 发送策略）默认 200 条/小时、1000 条/天，客户可以填 0（不限）；平台暂未做强制封顶。
- AI 接待、背调等后台任务所有客户共用线程池；客户多了以后需要按客户限流。
- 上传的文件链接不需要登录就能打开（链接难猜但不是权限控制），后续改为私有存储 + 签名链接。
